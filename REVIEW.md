# REVIEW.md

Below is the structured list of all defects identified and fixed in `app/main.py`:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 36-40) | Missing IST timezone conversion, overnight shift handling, and uses integer division floor instead of checking strict > 10 min grace threshold against shift start in IST. | Pass `09:40:01` IST for a `09:30` shift: returned 10 on naive timestamp, or failed overnight shifts where `shift_start` is `22:00`. | Converted timestamp to IST, constructed `shift_start` datetime in IST on the record's attendance date, and checked `delta > 600` seconds to return `int(delta // 60)`. |
| 2 | `compute_work_hours` (line 44) | Uses Python's built-in `round()` which applies banker's rounding (round-to-even) instead of R4 half-up rounding. | Duration resulting in `.005` (e.g., 2.675 -> `round(2.675, 2)` gives `2.67` instead of `2.68`). | Replaced with `Decimal` division quantized to 2 decimals using `ROUND_HALF_UP`. |
| 3 | `compute_overtime` (lines 47-50) | Missing IST conversion, fails to handle overnight shift end falling on next calendar day, and counts overtime for any duration > 0 without checking the 30-minute minimum threshold (R3). | Punch-out 20 minutes after `shift_end` returned 20 instead of 0. Overnight shifts calculated `shift_end` on the wrong day. | Constructed `shift_end` in IST (adding 1 day for overnight shifts) and returned `int(delta // 60)` only when `delta >= 1800` seconds (30 mins). |
| 4 | `POST /employees` (lines 80-88) | Vulnerable to race conditions under concurrent creates (check-then-insert), sets `created_at` as local naive `datetime.now()` (returned as ISO string instead of epoch ms integer), and lacks validation on `emp_code` regex and `shift_start != shift_end`. | Concurrent POST requests with identical `emp_code` resulted in duplicate inserts or 500 errors. `created_at` response field failed OpenAPI schema. | Added unique index on `emp_code`, handled `DuplicateKeyError` with 409, set `created_at` to UTC datetime serialized to epoch ms, and added Pydantic regex/equality validation. |
| 5 | `POST /attendance/punch-in` (lines 127-149) | Check-then-insert race condition on `(emp_code, date)`, computes `date` from UTC instead of IST (violating R1 overnight rules), returns non-spec `id` field, missing employee 404 check, and accepts non-presence statuses. | Concurrent punch-ins for same date passed check. Punch-in at 01:00 UTC calculated wrong calendar date. Returned `id` field breaking OpenAPI contract. Non-existent employee returned 201. | Created unique compound index on `(emp_code, date)` handling `DuplicateKeyError` with 409, implemented R1 IST date calculation, removed `id` field from response, checked employee existence (404), and validated status enum. |
| 6 | `GET /attendance` (lines 152-178) | Loads all matching documents into Python memory with `list(find())` and sorts in Python, causing extreme latency and OOM at 100k scale. Also returns non-spec `id` field and misses `date_from > date_to` validation. | High latency (> seconds) on 100k dataset. Returned documents contained `id` instead of spec schema, and invalid date range returned 200 instead of 422. | Replaced in-memory sorting with MongoDB `.sort([("date", -1), ("emp_code", 1)])`, `.skip()`, and `.limit()`. Removed `id` field, formatted datetime fields to epoch ms, and added 422 validation for date range. |
| 7 | `GET /health` (lines 75-77) | Returns 200 OK unconditionally without probing MongoDB readiness. | When MongoDB was down or unreachable, `GET /health` returned 200 instead of 503 Service Unavailable. | Added `db.command("ping")` inside `try...except`, raising `HTTPException(503)` if MongoDB ping fails. |
| 8 | Global / Startup (lines 22-30) | No database index creation logic at app startup. `MongoClient` initialized without `tz_aware=True`. | Database had only `_id` index. Queries on 100k records performed `COLLSCAN`. Timestamps shifted due to naive local timezone parsing. | Added `@app.on_event("startup")` handler creating all required unique and compound indexes idempotently. Set `tz_aware=True` on `MongoClient`. |
| 9 | Pydantic Models (lines 56-70) | `punched_at` in `PunchInIn` allowed unvalidated input (e.g. floats, out-of-range numbers, or seconds-looking ints < 100000000000). | Passing `punched_at: 1700000000` (seconds) was accepted with 201 instead of returning 422 validation error. | Implemented custom validator `validate_epoch_ms` enforcing integer type and range `[100000000000, 4102444800000]`. |
| 10 | BSON Datetime Serialization | Returned raw BSON `datetime` objects in FastAPI responses, which FastAPI serialized to ISO-8601 strings instead of epoch milliseconds `int64`. | API responses contained `"punch_in": "2026-07-06T03:58:00Z"` instead of `"punch_in": 1783312500000`. | Added recursive document formatter `format_attendance_doc` / `format_employee_doc` converting all datetimes to integer epoch milliseconds. |

---

### Code Examined and Decided as Not a Defect:
- **`GET /employees` pagination bounds check (`page < 1`, `page_size > 100`)**: The validation logic in starter line 97-101 was examined and found to correctly enforce page bounds (returning 422 on invalid inputs), so it was retained and converted to FastAPI `Query` parameters for cleaner OpenAPI schema generation.
- **Pydantic Model default shift times (`09:30` and `18:30`)**: Standard shift defaults match the OpenAPI specification defaults.
